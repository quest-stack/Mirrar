## はじめに

Mirarrは、プログラミング知識がなくても使えるテスト自動化ツールです。

### こんな人におすすめ

- プログラミング経験がない
- でもWebアプリのテストを自動化したい
- Playwrightは難しすぎた
- 無料で使いたい

### Mirarrでできること

- ✅ ログイン機能のテスト
- ✅ フォーム送信のテスト
- ✅ 商品購入フローのテスト
- ✅ 検索機能のテスト
- ✅ その他、あらゆるブラウザ操作のテスト

## 初めてのテスト作成

### ステップ1: 新規テスト作成

1. アプリを起動
2. 「新しいテストを作成」ボタンをクリック

### ステップ2: テンプレートを選択

例として「ログイン機能をテストする」を選んでみましょう。

### ステップ3: URLを入力

ログインページのURLを入力します。

例: `https://example.com/login`

### ステップ4: 要素を選択

ガイドに従って、以下の要素を選択：

1. **メールアドレス入力欄**
   - 画面に表示される入力欄をクリック
   - 自動検出されたら ✅ マークが表示されます

2. **パスワード入力欄**
   - 同様に入力欄をクリック

3. **ログインボタン**
   - ログインボタンをクリック

### ステップ5: テストデータを入力

テスト用のデータを入力：

- メール: `test@example.com`
- パスワード: `testpassword123`

**注意**: 本番のパスワードは使わないでください！

### ステップ6: テスト実行

「テストを実行」ボタンをクリック。

ブラウザが自動で開いて、入力した操作が自動で実行されます！

### ステップ7: 結果を確認

テスト完了後、以下が表示されます：

- ✅ 各ステップの成功/失敗
- 📸 スクリーンショット
- 🎥 実行動画
- ⏱️ 実行時間

## 🤖 AIツール連携（Vibe Coding スタイル）

### Vibe Coding とは？

**Vibe Coding** = Claude Code、Cursor、Windsurf、GitHub Copilot等のAIツールを使った開発スタイル

Mirarrと連携することで、テストの問題をAIに解決してもらえます。

### 対応しているAIツール

- ✅ **Claude Code** - Anthropic公式CLI
- ✅ **Cursor** - AI搭載エディタ
- ✅ **Windsurf** - Codeium AI
- ✅ **GitHub Copilot** - GitHub AI
- ✅ **ChatGPT** - ブラウザ版も可
- ✅ その他、テキストプロンプトに対応するAIツール全般

### 使い方

#### ステップ1: テストが失敗したら

テスト実行後、失敗したステップがあったら「**AIツールに修正を依頼**」ボタンが表示されます。

#### ステップ2: プロンプトをコピー

ボタンをクリックすると、問題を説明するプロンプトが自動生成され、クリップボードにコピーされます。

**生成されるプロンプト例**:
```
以下のテストステップが失敗しました：

ステップ3: "ログインボタンをクリック"
エラー: Element not found - セレクター '[data-testid="login-btn"]' が見つかりません

ページURL: https://example.com/login
スクリーンショット: [添付画像]

このボタンを検出するための最適なセレクター戦略を提案してください。
```

#### ステップ3: 普段使っているAIツールに貼り付け

**Claude Code の場合**:
```bash
# ターミナルで実行中のClaude Codeに貼り付け
Ctrl+V (Mac: Cmd+V)
```

**Cursor / Windsurf の場合**:
1. Ctrl+L (Mac: Cmd+L) でチャットを開く
2. Ctrl+V (Mac: Cmd+V) でプロンプトを貼り付け
3. Enter で実行

**ChatGPT / ブラウザAI の場合**:
1. ブラウザでChatGPTを開く
2. プロンプトを貼り付け
3. 送信

#### ステップ4: 結果を適用

1. AIツールが生成した修正案をコピー
2. Mirarrに戻る
3. 「**適用**」ボタンを押す
4. テストを再実行

### 実例: ログインボタンが見つからない問題の解決

#### 問題発生

```
❌ ステップ3失敗: "ログインボタンをクリック"
エラー: Element not found
```

#### AIツールに依頼

Mirarrが生成したプロンプト:
```
ログインボタンのセレクターが見つかりません。
以下のHTML構造で、最も確実にボタンを検出する方法を教えてください：

<div class="form-actions">
  <button type="submit" class="btn btn-primary">ログイン</button>
</div>
```

#### AIツールの回答例（Claude Code）

```
以下の検出戦略をお勧めします：

1. type属性で検出:
   セレクター: button[type="submit"]
   信頼度: 高

2. テキストで検出:
   セレクター: button:has-text("ログイン")
   信頼度: 高

3. CSSクラスで検出:
   セレクター: .btn-primary
   信頼度: 中（他のボタンにも使われる可能性）

推奨: テキストベースの検出が最も確実です。
```

#### 適用して再実行

```
✅ ステップ3成功: "ログインボタンをクリック" (0.8秒)
```

### プロンプトの種類

#### 1. セレクター修正

**いつ使う**: 要素が見つからない場合

**プロンプト例**:
```
「送信ボタン」をクリックしたいが、以下のセレクターで見つかりません:
- [data-testid="submit"]
- #submit-btn
- .submit-button

ページHTML: <form>...</form>

最適なセレクターを提案してください。
```

#### 2. テスト自動生成

**いつ使う**: ゼロからテストを作りたい場合

**プロンプト例**:
```
以下のページのログインテストを作成してください:
URL: https://example.com/login

要件:
- メールアドレス入力
- パスワード入力
- ログインボタンクリック
- ダッシュボード表示確認

Mirarr形式のJSON定義で出力してください。
```

#### 3. 検証項目提案

**いつ使う**: テストの抜け漏れを防ぎたい場合

**プロンプト例**:
```
ECサイトの購入フローテストを作成中です。
現在のステップ:
1. 商品をカートに追加
2. カートを表示
3. 購入手続きへ進む

追加すべき検証項目を提案してください。
```

#### 4. デバッグ支援

**いつ使う**: エラーの原因がわからない場合

**プロンプト例**:
```
以下のエラーが発生します:
TimeoutError: waiting for selector `#product-list` failed: timeout 30000ms exceeded

ページURL: https://example.com/search?q=laptop
スクリーンショット: [添付]

原因と解決方法を教えてください。
```

### セキュリティ注意事項

⚠️ **AIツールに送信する前に、必ず以下を確認してください**:

- ✅ 本番のパスワードが含まれていないか
- ✅ APIキーやトークンが含まれていないか
- ✅ 個人情報（実名、住所、電話番号）が含まれていないか

Mirarrは自動的にチェックしますが、**手動でも確認してください**。

**安全なプロンプト例**:
```
❌ NG: メールに yamada@company.com、パスワードに MyRealPass123 を入力
✅ OK: メールに test@example.com、パスワードに testpassword を入力
```

## よくある質問

### 📌 基本的な質問

#### Q: プログラミング知識は必要ですか？

**A**: まったく不要です！以下の操作ができれば使えます：
- ブラウザでWebサイトを開く
- マウスでクリック
- キーボードで文字を入力

コードを書く必要は一切ありません。

#### Q: 無料で使えますか？料金はかかりますか？

**A**: **完全無料**です！
- ✅ アプリのダウンロード: 無料
- ✅ 機能制限: なし
- ✅ APIコスト: ゼロ（全てローカルで動作）
- ✅ 有料プランへのアップセル: なし

永久無料で、すべての機能が使えます。

#### Q: Playwrightとの違いは何ですか？

**A**:

| 比較項目 | Mirarr | Playwright |
|---------|-------------------|-----------|
| **プログラミング** | 不要 | 必要（JavaScript/TypeScript） |
| **テスト作成** | テンプレート選択＋GUI操作 | コードを書く |
| **学習コスト** | 10分 | 数週間〜数ヶ月 |
| **要素検出** | 自動（5戦略） | 手動（セレクター指定） |
| **AI連携** | 組み込み | なし |
| **価格** | 無料 | 無料（有料サポートあり） |

**使い分け**:
- 非エンジニア、簡単なテスト → Mirarr
- エンジニア、複雑なテスト → Playwright

### 🛠️ 技術的な質問

#### Q: どんなブラウザに対応していますか？

**A**: **Chromiumベース**のブラウザで動作します：
- ✅ Google Chrome
- ✅ Microsoft Edge
- ✅ Brave
- ✅ Opera
- ❌ Firefox（未対応）
- ❌ Safari（未対応）

将来的にFirefox、Safariにも対応予定です。

#### Q: テストデータは安全ですか？どこに保存されますか？

**A**: **100%安全**です：
- ✅ すべて**ローカル**に保存（あなたのPC内）
- ✅ 外部サーバーへの送信: **一切なし**
- ✅ クラウド同期: **オプション**（Turso使用時のみ、ユーザー選択）

**保存場所**:
- Windows: `C:\Users\<ユーザー名>\AppData\Roaming\auto-pailot-tester`
- Mac: `~/Library/Application Support/auto-pailot-tester`
- Linux: `~/.config/auto-pailot-tester`

#### Q: 本番環境のテストに使えますか？

**A**: **推奨しません**。以下の理由から：
1. 本番データの破壊リスク
2. 誤操作による顧客への影響
3. パスワード漏洩リスク

**推奨環境**:
- ✅ ステージング環境（本番に似たテスト環境）
- ✅ 開発環境
- ✅ ローカル環境

本番テストが必要な場合は、**読み取り専用の操作のみ**にしてください。

### 🤖 AI連携の質問

#### Q: AIツール（Claude Code、Cursor等）以外も使えますか？

**A**: **はい！** 任意のAIツールが使えます：
- ✅ **Claude Code** - Anthropic公式CLI
- ✅ **Cursor** - AI搭載エディタ
- ✅ **Windsurf** - Codeium AI

- テスト実行: AIなしで可能

AIツールは「困ったときの助っ人」として使えます。

### ⚠️ トラブル関連の質問

#### Q: テストが途中で止まってしまいます

**A**: 以下を確認してください：

1. **タイムアウト設定**: デフォルト30秒 → 長いページは設定で延長
2. **待機ステップ追加**: `3秒待つ` を追加
3. **ネットワーク**: インターネット接続を確認

詳細は[トラブルシューティング](#トラブルシューティング)へ。

#### Q: 「Element not found」エラーが頻発します

**A**: 要素検出の問題です。以下を試してください：

1. **AIツールに依頼**: 「AIツールに修正を依頼」ボタン
2. **検出戦略変更**: 設定で優先戦略を変更
3. **待機時間追加**: ページ読み込み完了を待つ

#### Q: 録画されたビデオが再生できません

**A**: 以下の形式で保存されます：
- **形式**: MP4（H.264コーデック）
- **推奨プレイヤー**: VLC、Windows Media Player、QuickTime

再生できない場合は[VLCプレイヤー](https://www.videolan.org/)をインストールしてください。

### エラー1: "Element not found" - 要素が見つからない

**エラーメッセージ例**:
```
❌ ステップ3失敗: "ログインボタンをクリック"
ElementNotFoundError: セレクター '[data-testid="login"]' が見つかりません
```

#### 原因A: ページの読み込みが完了していない

**症状**: ページ遷移直後のステップで失敗する

**解決方法**:
```
# 待機ステップを追加
https://example.com/loginを開く
3秒待つ  ← これを追加
メールアドレスを入力
```

**設定で待機時間を増やす**:
1. 設定 → タイムアウト設定
2. デフォルト待機時間: `3秒` → `5秒` に変更

#### 原因B: セレクター戦略が合っていない

**症状**: 特定の要素だけ常に失敗する

**解決方法1 - AIツールに依頼**:
1. 「AIツールに修正を依頼」ボタンをクリック
2. Claude Code/Cursor/Windsurf に貼り付け
3. 提案されたセレクターを適用

**解決方法2 - 検出戦略を変更**:
1. テスト編集画面を開く
2. 失敗したステップをクリック
3. 「検出戦略」タブ → 優先戦略を変更
   - `testid` → `text` に変更
   - `label` → `aria` に変更

**解決方法3 - 手動でセレクターを指定**:
```json
{
  "type": "click",
  "description": "ログインボタンをクリック",
  "selector": "button.login-btn",  // 手動指定
  "detectionStrategy": "manual"
}
```

#### 原因C: 動的に生成される要素（JavaScript）

**症状**: 「要素があるのに見つからない」

**解決方法**:
```
# JavaScriptによる描画を待つ
商品一覧ページを開く
5秒待つ  ← JavaScript実行を待つ
最初の商品をクリック
```

**より良い方法**:
```
# 特定の要素が表示されるまで待つ（今後実装予定）
商品一覧ページを開く
商品リストが表示されるまで待つ  ← 条件付き待機
最初の商品をクリック
```

### エラー2: "Timeout exceeded" - タイムアウト

**エラーメッセージ例**:
```
❌ ステップ5失敗: "検索結果が表示されるのを待つ"
TimeoutError: waiting for selector '#results' failed: timeout 30000ms exceeded
```

#### 原因A: ページ読み込みが遅い

**症状**: 特定のページでいつもタイムアウト

**解決方法**:
```
# タイムアウトを個別に延長
検索ボタンをクリック
60秒待つ  ← 長めに設定
検索結果を確認
```

**グローバル設定で変更**:
1. 設定 → タイムアウト設定
2. 要素検出タイムアウト: `30秒` → `60秒`

#### 原因B: ネットワークが遅い

**症状**: すべてのテストが遅い

**確認方法**:
```bash
# インターネット速度をチェック
ping google.com
```

**解決方法**:
- Wi-Fiを再接続
- 有線LANに切り替え
- ネットワークが安定してから実行

#### 原因C: サーバー側の問題

**症状**: 以前は動いていたテストが急に失敗

**確認方法**:
1. ブラウザで手動アクセスしてみる
2. サーバーが正常か確認

**解決方法**:
- サーバーが復旧するまで待つ
- テスト対象URLを変更（ステージング環境等）

### エラー3: "Network error" - ネットワークエラー

**エラーメッセージ例**:
```
❌ ステップ1失敗: "https://example.comを開く"
NetworkError: net::ERR_NAME_NOT_RESOLVED
```

#### 原因A: インターネット未接続

**確認方法**:
```bash
ping 8.8.8.8
```

**解決方法**:
- Wi-Fi/LANケーブルを確認
- ルーターを再起動

#### 原因B: URLが間違っている

**症状**: 特定のURLだけエラー

**確認方法**:
```
❌ 間違い: example.com  ← https:// がない
✅ 正しい: https://example.com
```

**解決方法**: URLを修正

#### 原因C: ファイアウォール・プロキシ

**症状**: 社内ネットワークで動かない

**解決方法**:
1. 設定 → ネットワーク → プロキシ設定
2. プロキシサーバー情報を入力
   - ホスト: `proxy.company.com`
   - ポート: `8080`

### エラー4: テストが途中で止まる

**症状**: スピナーがずっと回っている、進まない

#### 原因A: モーダル・ポップアップが邪魔している

**例**: クッキー同意バナー、広告ポップアップ

**解決方法**:
```
# テストの最初に閉じるステップを追加

2秒待つ
クッキー同意ボタンをクリック  ← 追加
広告を閉じるをクリック  ← 追加
メインの操作を開始
```

#### 原因B: 無限ループ

**症状**: 同じステップを延々と繰り返す（今後実装予定の機能で発生可能性）

**解決方法**:
- アプリを強制終了（Ctrl+C または ウィンドウを閉じる）
- テストロジックを見直す

### エラー6: 録画・スクリーンショットが保存されない

**症状**: テストは成功するが、動画や画像がない

#### 原因A: ディスク容量不足

**症状**: macOSで「アクセス許可がない」エラー

**解決方法**:
1. システム環境設定 → セキュリティとプライバシー
2. フルディスクアクセス → Mirarr を許可

### パフォーマンス問題

### 問題A: 動作が遅い

**症状**: テスト実行に異常に時間がかかる

**解決方法1 - 不要な待機を削除**:
```
❌ 遅い:
ログインボタンをクリック
10秒待つ  ← 長すぎる
次へ進む

✅ 速い:
ログインボタンをクリック
2秒待つ  ← 必要最小限
次へ進む
```

**解決方法2 - ヘッドレスモードを使う**:
1. 設定 → 実行モード
2. 「ヘッドレスモード」をON（ブラウザを表示しない）
3. 実行速度が2〜3倍速くなります

**解決方法3 - 録画を無効化**:
1. 設定 → 録画設定
2. 「ビデオ録画」をOFF
3. スクリーンショットのみ保存

### 問題B: メモリ不足

**症状**: 複数のテストを連続実行するとクラッシュ

**解決方法**:
- テストを分割して実行
- PCを再起動してから実行
- メモリを増設（8GB以上推奨）

### デバッグのヒント

#### 1. スクリーンショットで確認

テスト失敗時、自動的に撮影されたスクリーンショットを確認：
```
results/
  └── login_test_20240115_123045/
      ├── step_1.png  ← ページを開いた時
      ├── step_2.png  ← メール入力後
      ├── step_3.png  ← ❌ ここで失敗
```

**step_3.png を見て原因を特定**:
- 要素が表示されているか？
- ローディング中か？
- エラーメッセージが出ているか？

#### 2. スローモーションモードを使う

1. 設定 → 実行速度
2. 「スローモーション」をON
3. 各ステップがゆっくり実行される（問題箇所を目視確認）

#### 3. ステップバイステップ実行

1. テスト編集画面
2. 「デバッグモード」をON
3. 1ステップずつ手動で実行（Enterキーで次へ）

**プロンプト例**:
```

エラー: Element not found - [data-testid="submit"]

考えられる原因と解決策を教えてください。
```
